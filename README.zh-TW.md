# Witcut

**有目的地剪輯，忠於真實。**

將真實 UI 操作製作成清楚、有設計感、可驗證的產品展示影片。

[English](README.md) · [Skill 入口](skills/witcut/SKILL.md)

## 現在能做什麼？

Witcut 目前是 **agent 可使用的製作工作流 skill**：協助規劃分鏡、錄製真實操作、有目的地剪輯、檢查交付檔，以及整理可恢復的製作交接。

它**還不是自動剪輯引擎或雲端服務**。需要執行環境原本就有錄製、剪輯、檢視工具與使用權限。Python 規劃工具檢查套件結構與證據連結資料；另有可選的單一 FFmpeg adapter，僅渲染原創合成測試短片，不錄製真實 UI，也不認證影片品質。

## 核心原則

- 先理解真實功能：獨立模式不能被說成連續流程；手動操作不能被剪成自動完成。
- 每段 zoom 都要有目的，並檢查放大前、移動中、放大後的構圖。
- 解析度不等於 UI 大小；browser zoom、DPR、錄製與輸出解析度要分開處理。
- 時長服從理解，不為了湊一分鐘刪掉必要結果。
- 技術檢查、藝術判斷、音訊信號、實際聆聽、播放裝置與使用者驗收分開記錄。
- 尊重「只檢視，不改檔」和已凍結版本，不陷入無限打磨。
- 備份回讀成功不等於已在乾淨環境完整重建。

150%、4K、16:9、片長與配樂都是個案設定，不是強制規範。

## 使用

將完整 `skills/witcut` 資料夾放入 agent 支援的 skill 目錄；不支援自動發現的環境，可直接指定 `SKILL.md` 作為入口，並允許讀取相關 references。

範例：

> 使用 Witcut 檢視這支產品影片，特別檢查 zoom 是否幫助理解。只回報時間碼與問題，先不要改檔。

> 使用 Witcut 為這個產品規劃展示影片。先驗證各模式的關係，再做短版錄製測試。

## 發展方向

先把真實操作、構圖、驗收與交接做好，再逐步建立分鏡資料格式、渲染介接、技術自動檢查與可審查的自動粗剪。這些仍是 roadmap，不能視為現成功能。

驗證指令及完整說明見 [英文 README](README.md)。目前尚未選定授權條款，也未附帶第三方影片、音樂或品牌素材。

## 結構化規劃核心

已提供[共用規劃核心](skills/witcut/references/planning.md)，分為產品展示與 Podcast 轉影片兩種 profile，由同一份輸入產出影音分鏡劇本、機器可讀 shot plan 與缺件清單。範例是原創合成文字 fixture，不是實際錄影或矽聲電台素材；驗證通過不代表媒體、授權或語意已查證。規劃格式 v2 明確記錄來源到輸出時間；v1 需人工確認映射後遷移。另有[受限的原創合成短片 adapter](skills/witcut/references/render-fixture.md)，尚非通用 renderer；文件列出可選的 FFmpeg 語音依賴與生成、重現命令。缺依賴時整合測試會明確 skip，不影響標準函式庫規劃工具。

[協作策略](skills/witcut/references/collaboration.md) 依環境可用能力選擇模型與推理設定，界定企劃、素材、執行、獨立審查責任。各層使用有限 loop，最上層仍須驗收觀眾理解，不能用子任務全過替代。
