# Evidence-linked planning core (v2)

Use `../scripts/plan.py` and the [product-demo fixture](../examples/plans/product-demo.json) or [podcast-to-video fixture](../examples/plans/podcast-to-video.json). These are original synthetic, text-only fixtures, not captured media, private radio content, or rights-clearance examples.

The executable `SCHEMA` in `plan.py` is the strict format authority: all keys required, unknown keys rejected, numeric seconds finite. `version` is the string `2`. Version 1 is rejected rather than silently assigning timing. To migrate, set version 2 and explicitly add `output_start`, `output_end`, and `playback` to every evidence reference; review each mapping before accepting the result. CLI (from repository root):

```sh
python3 skills/witcut/scripts/plan.py skills/witcut/examples/plans/product-demo.json --out /tmp/witcut-plan
```

The output directory must not exist. Exit 0 means structural/timeline/evidence-link checks passed, **not** that the story or footage is verified. Missing production materials may remain. Invalid input exits 1 and reports errors; no artifacts are emitted. Outputs are `script.md`, `shot-plan.json`, and `missing-materials.json`, all derived from one input. The shot plan includes accumulated timeline coordinates; it is an output artifact, not an editable input round-trip format.

## Plan and review

- Brief: identify the latest revision, actual duration bounds and required operations. Caller must check the latest brief externally; equal revision strings cannot establish freshness.
- Sources: declare `modality` (`audio`, `visual`, `audiovisual`, or `script`), actual duration and provenance; `real` means observed documentary/product source, never AI-generated or editorially fabricated imagery. Production graphics, AI images, reenactments, and other non-documentary assets use `editorial`, not `real` or `synthetic-fixture`; they cannot prove a `current` claim. Both production kinds use `verified`/`unverified` and `cleared`/`unknown`. Synthetic fixtures must use `fixture` and `fixture-only`. These fields record supplied assertions; this tool does not open media, verify a license, or certify an observation.
- Operations: every inventoried operation must appear in a scene or carry an explicit nonempty `omission_reason`; shown operations use an empty reason. Required operations cannot be omitted even with a reason. Review omissions for hidden manual prerequisites. Record observable/manual actions, source ranges, and `independent` or `sequential` relationships. Independent alternatives cannot list predecessors. Sequential dependencies must be acyclic and appear earlier in output time; operation ID array order within a scene carries no timing meaning; same-source predecessor ranges must precede their successors. Different-source continuity must be reviewed by a person/agent against actual evidence.
- Timing: each reference maps source `start`/`end` to scene-local `output_start`/`output_end` (seconds, bounded by scene duration). `play` means 1x continuous playback and requires equal source/output lengths; speed changes are unsupported. `hold` is visual-only and selects the source frame at `start`; its source range is evidence context, not played action. `reference` is planning context only, not rendered evidence. Script references require a recording before playback. A held frame or narration alone cannot count as a shown operation. Sequential operations within a scene must also appear in mapped time order. Global scene coordinates are derived, never edited independently.
- Scenes: evidence references declare a `role` (`narration`, `visual`, or `both`) compatible with source modality. Audio/script evidence cannot prove a current visual state. Missing visual or narration evidence is listed separately. Write purpose, exact spoken text (empty for silence), visual direction, and an explicit audio/visual alignment rationale. Reference exactly one unambiguous played visual evidence range covering each shown operation; narrated explanation cannot satisfy a required demonstration. Declare `current`, `intended`, or `illustrative`; current claims require verified real evidence, intended states enter the missing-material list. State missing assets in `needs` rather than inventing sources. Editorial visuals must be identified as such; they are not documentary evidence.
- Product-demo requires explicit required operations; podcast-to-video requires spoken text. Neither profile implies a particular length, aspect ratio, voice, existing episode, or rights grant.

Human review remains necessary: compare each spoken assertion with the actual visible state, inspect causal claims (including transitions between independent tools), confirm the alignment rationale, speaking/reading pace, privacy, and rights. Nonempty prose is not semantic proof. Use an unseen/adversarial plan as well as the shipped examples. Use the finite [shared loop contract](collaboration.md): fix blocking findings locally within the agreed budget, or report the exact missing access/authority. Never infer semantic proof from a passing validator.

## Not shipped

No transcription, automatic screenplay reasoning, semantic fact-checker, semantic footage inspection, general renderer, capture adapter, or delivery certification. The mapping is sufficient for bounded 1x planning, not a general edit timeline: no implicit looping, speed changes, track mixing, or rendering from prose. A single adapter can resolve source IDs into paths/hashes and project these coordinates into a separate execution manifest without changing the planning model. The [single synthetic fixture adapter](render-fixture.md) exercises this boundary with actual local media. Keep production approval separate from planning validation.
